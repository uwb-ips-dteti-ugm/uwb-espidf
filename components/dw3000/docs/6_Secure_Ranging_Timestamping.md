## Overview

Secure timestamping is one of the primary differentiators between the DW3000 and DW1000.

### DW1000 Baseline (Unsecured)

The DW1000 derives its sub-nanosecond RX timestamp from CIR (Channel Impulse Response) accumulation of the preamble sequence. When the SFD is detected, a coarse timestamp is taken, then the accumulated CIR (representing the radio channel impulse response) is used by the CIA algorithm to find the first arriving ray and adjust the timestamp to sub-nanosecond precision.

### Attack Vector on Preamble-Based Timestamping

Because the preamble is a **publicly known, repeated symbol sequence**, an attacker can:
1. Replay or retransmit the same preamble code with a small time offset
2. This forged signal appears as an **earlier arriving ray** in the CIR
3. The IC reports a shorter ToA → foreshortened ranging result → attacker appears closer than they actually are

This attack can fool access control systems into granting entry to an attacker.

## STS — Scrambled Timestamp Sequence

To defeat this attack, the DW3000 includes an **STS (Scrambled Timestamp Sequence)** in the UWB packet, as defined by the **IEEE 802.15.4z amendment** [2].

### How STS Works

- The STS is a sequence of pseudo-randomised positive and negative polarity pulses generated by an **AES-128 CPRNG** (Cryptographic Pseudo-Random Number Generator) in counter mode — also called a **DRBG (Deterministic Random Bit Generator)**
- Only transmitters and receivers sharing the **same seed (key + nonce)** can generate and correlate the sequence
- An attacker without the key cannot predict the next STS pattern, so cannot forge an earlier-arriving signal
- The resultant RX timestamp derived from STS CIR correlation is **secure against replay and injection attacks**

### STS Structure (Figure 24)

```
     ┌───────┬──────────────────┬───────┐
     │  Gap  │   STS active     │  Gap  │
     └───────┴──────────────────┴───────┘
     ←────── Single segment STS ────────→

  Gap = 512 chips (~1 µs) on each side
```

- STS length is specified in units of **512 chips (~1 µs)** — also called an *STS symbol*
- In BPRF mode (8-chip pulse spacing), one 512-chip unit contains **64 pulses** at 64 MHz PRF
- **Minimum length (IEEE 802.15.4z mandate):** 64 units = 4096 pulses ≈ **64 µs duration**
- **Programmable range:** 32 to 2048 units (steps of 8 units, each step ≈ 8 µs)

Configure STS length via `CPS_LEN` field in `STS_CFG` register.

## STS Packet Configuration Modes

Three STS placement modes are available, selected via the `CP_SPC` field in Sub-register `0x00:10` (System configuration). See also packet formats SP0–SP3 in Chapter 3.

### SP1 — STS Directly After SFD (Mode 1)

```
[Preamble][SFD][STS][PHR][Data]
```

- STS arrives early in a **deterministic position** after the SFD
- CIA can begin processing the STS CIR earlier (in parallel with PHR/data reception)
- Saves time and energy compared to SP2
- **Drawback:** If STS seeds are misaligned (key/nonce mismatch), data reception performance may be degraded

### SP2 — STS at End of Packet (Mode 2)

```
[Preamble][SFD][PHR][Data][STS]
```

- STS arrives after the data payload
- **Advantage:** Data is received normally even if STS seeds are misaligned
- Packets are compatible with original IEEE 802.15.4 UWB receivers (which can receive the data portion even without STS support)
- The frame payload can carry **seed synchronisation information** (key + nonce counter state) to achieve STS alignment for future exchanges
- > **Important:** Data length must be **non-zero** for correct operation in SP2 mode

#### SP2 Security Note

SP2 can be attacked: an attacker can corrupt the PHR to indicate a longer payload, append data with a valid CRC, while recording and replaying the true STS at a shifted alignment to produce an earlier ToA. **Countermeasures:**
- Ensure the true message length is either a constant or is included in an encrypted payload
- Encrypt the data payload — the attacker cannot forge a valid MIC for the longer frame, and the receiver's security processing discards the frame

### SP3 — STS Only, No Data (Mode 3)

```
[Preamble][SFD][STS]
```

- STS directly after SFD; **no PHR or PHY payload**
- Saves maximum time and energy
- No data portion means no attack surface for payload-length forgery
- Used in ranging-only scenarios where no data transfer is needed

## STS Key and Nonce

### Registers

| Register  | Width   | Description                              |
| --------- | ------- | ---------------------------------------- |
| `STS_KEY` | 128-bit | AES key used to generate STS sequence    |
| `STS_IV`  | 128-bit | Initial nonce value (IV = Initial Value) |

### CPRNG Operation (Figure 25)

```
  ┌──────────────┐   ┌─────────────────┐   ┌──────────┐
  │   Counter    │   │  Upper 96 bits  │   │  StsKey  │
  │ (32-bit,     │   │  (from STS_IV,  │   │ (128-bit)│
  │  lower bits  │   │   fixed)        │   │          │
  │  of nonce)   │   │                 │   │          │
  └──────┬───────┘   └────────┬────────┘   └────┬─────┘
         │                    │                  │
         └────────────────────┘                  │
                    128-bit nonce                │
                         │                       │
                         ▼                       │
                    ┌─────────┐ ←── 128-bit key ─┘
                    │ AES-128 │
                    └────┬────┘
                         ▼
               128-bit pseudo random number
               → used to form 128 pulses of STS

  Counter increments: +1 per 128 pulses output
                      +32 per completed TX/RX of IEEE 802.15.4z
                           mandated 64-unit (4096 pulse) BPRF STS
```

### Counter Alignment in Two-Way Ranging

- Both transmitter and receiver must use **same STS length, same key, and same nonce** (including counter state)
- The counter auto-advances identically in both devices as messages are sent/received in a standard TWR exchange — counter state stays naturally aligned
- To **resync** after misalignment (or in multi-node systems): reprogram the counter state into the `STS_IV` register, or send the counter state from one device to another

> **Critical:** During STS generation (TX or RX), the counter state is in flux. **Do NOT read or write `STS_IV`** while the DW3000 is actively transmitting or receiving. Ensure the device is idle before accessing `STS_IV`.

## CIA Processing of STS CIR

When STS is included in the packet, the DW3000 performs **two separate CIR accumulations**:

1. **Preamble CIR** — accumulated during preamble reception (same as non-STS operation)
2. **STS CIR** — accumulated during STS reception

Both CIRs are accessible via Register `0x15` (Accumulator CIR memory).

> **Note:** Do **not** read `ACC_MEM` until the CIA has finished processing — wait for the `CIADONE` event status flag. Reading before CIA completion may conflict with CIA's own memory accesses and corrupt the RX timestamp.

The CIA processes the CIR to find the leading edge (first arriving path). It can be applied to preamble CIR, STS CIR, or both. Configure via sub-registers `CP_CONF0`, `CP_CONF1`, `IP_CONF0`, `IP_CONF1`.

When both CIRs are present, CIA runs on the **preamble CIR first, then the STS CIR**.

The final RX timestamp is delivered via the `RX_STAMP` field in Sub-register `0x00:64`.

## STS Quality Assessment

Before trusting an STS-based timestamp in a ranging exchange, always verify STS quality:

### CP_TOAST Quality Indicator

- `CP_TOAST` quality status indicator in register `CP_TS`
- If `CP_TOAST` indicates a problem, the STS CIR analysis result is unreliable — **discard the timestamp**

### CPS_ACCQUAL Threshold

The `CPS_ACCQUAL` field in `STS_STS` register provides a unitless quality metric of the STS accumulation:

- **Rule:** If `CPS_ACCQUAL < 60% of STS length` → STS reception was too poor for reliable first-path analysis → **do not use the STS-based timestamp**

**Example:**
- STS length = 128 units (`CPS_LEN` = 15), 64 MHz PRF (`TX_PCODE` in range 9–12)
- Trust `CP_TOA` only if `CPS_ACCQUAL ≥ 77` (= 60% × 128 = 76.8, rounded up)

## SDC — Super Deterministic Code

The DW3000 includes an alternative STS mode for environments where **security is not required** but collision resistance is still desired at high tag density.

- Enabled by setting the `CP_SDC` bit
- STS is populated with the **SDC (Super Deterministic Code)** instead of the AES-based scrambled sequence
- SDC is a time-varying sequence optimised for ToA performance — naturally tolerates packet collisions without requiring key management or counter synchronisation
- Increases confidence in ToA at high on-air packet density

> **Important:** SDC mode does **not** provide security against timestamp attacks. Use only when security is not a requirement.

| Mode          | Security | Collision resistance | Key management |
| ------------- | -------- | -------------------- | -------------- |
| AES-based STS | Yes      | High                 | Required       |
| SDC           | No       | High                 | None needed    |
