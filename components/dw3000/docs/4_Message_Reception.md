## 4.1 PHY Reception

The DW3000 can be enabled for reception from both **IDLE_RC** and **IDLE_PLL** states. Reception from IDLE_RC is limited — the PLL is not locked, so timing accuracy is reduced. Normal operation uses IDLE_PLL.

### RX Calibration

Before first use and after each wakeup from SLEEP/DEEPSLEEP, the **PGF (Programmable Gain Filter)** calibration must be run:

- API call: `dwt_pgf_cal()`
- Register: `RX_CAL` (0x11:0B)
- To perform automatically on wakeup: set `ONW_PGFCAL` bit in the AON configuration

Failure to calibrate results in degraded sensitivity.

### RX Sequence Flowchart

```
IDLE_PLL
    │
    │  CMD_RX / CMD_DRX / CMD_DRX_REF
    ▼
PREAMBLE SEARCH
    │  cross-correlate received signal against configured preamble code
    │  timeout: PRE_TOC (DTUNE0 register, 0x11:00)
    ▼
PREAMBLE ACCUMULATION
    │  build Channel Impulse Response (CIR) in accumulator memory
    ▼
SFD DETECTION  ──► RMARKER event (coarse RX timestamp)
    │  timeout: RX_SFDTOC (DTUNE0, default = 65 symbols)
    ▼
STS RECEPTION  (SP1, SP2, SP3 only)
    │  AES-based DRBG pulses; builds second CIR for secure ToA
    ▼
PHR DEMODULATION
    │  at 850 kb/s (optionally data rate if PHR_6M8 bit is set)
    ▼
DATA DEMODULATION
    │  Viterbi decoder + Reed-Solomon FEC + CRC check
    ▼
CIA (Channel Impulse Analyser)
    │  leading-edge detection → RX timestamp refinement
    ▼
IDLE_PLL  (frame received; status bits and timestamp latched)
```

## 4.1.1 Preamble Detection

The receiver cross-correlates the incoming signal against the **configured preamble code** (set in `CHAN_CTRL`). Detection occurs when the correlation peak exceeds the threshold set in `DTUNE0`.

### PAC Size Selection

**PAC (Preamble Acquisition Chunk)** is the number of preamble symbols correlated together per step. Larger PAC gives better sensitivity but requires a longer preamble.

| Preamble Length (PSR) | Recommended PAC (6.81 Mb/s) | Recommended PAC (850 kb/s) |
| --------------------- | --------------------------- | -------------------------- |
| 32                    | 4                           | 4                          |
| 64                    | 4                           | 4                          |
| 128                   | 8                           | 8                          |
| 256                   | 16                          | 16                         |
| 512                   | 16                          | 16                         |
| 1024                  | 32                          | 32                         |
| 2048                  | —                           | 32                         |
| 4096                  | —                           | 64                         |

PAC size is configured via `DTUNE0[1:0]` (0x11:00):

| DTUNE0[1:0] | PAC Size |
| ----------- | -------- |
| 00          | 4        |
| 01          | 8        |
| 10          | 16       |
| 11          | 32       |

> **Note:** PAC 64 is not directly configurable via DTUNE0 alone — use the recommended API `dwt_setpreambledetecttimeout()`.

A preamble detect timeout (`PRE_TOC` field in `DTUNE0`) should always be configured. If preamble is not found within the timeout, the `RXPTO` (RX Preamble Timeout) status bit is set and the receiver returns to idle.

---

## 4.1.2 Preamble Accumulation

Once the preamble correlator detects a candidate, the DW3000 begins **accumulating the CIR** (Channel Impulse Response) into the accumulator memory (readable via register `0x15`). This process continues while simultaneously searching for the SFD.

The CIR captures the multipath profile of the channel and is later analysed by the CIA to find the first-path arrival time.

---

## 4.1.3 SFD Detection

The **SFD (Start of Frame Delimiter)** marks the end of the preamble and the beginning of the PHR/data section.

At the moment the SFD is detected, the **RMARKER** (Ranging Marker) event occurs — this is the coarse RX timestamp reference point.

- Timeout register: `RX_SFDTOC` in `DTUNE0` (bits 15:8), default = **65 symbols**
- If SFD is not found within this window after preamble detect, `RXSTO` (RX SFD Timeout) status bit is set

> **WARNING:** Never set `RX_SFDTOC` to zero. A value of zero disables the timeout entirely, which can cause the receiver to hang indefinitely.

---

## 4.1.4 STS Reception

For packet configurations **SP1, SP2, and SP3** (see Chapter 3), the DW3000 receives the **STS (Scrambled Timestamp Sequence)** after the SFD (SP1, SP2) or directly after the SFD with no PHR/data (SP3).

- STS is generated by an **AES-128-based DRBG** (Deterministic Random Bit Generator)
- DW3000 correlates the received STS against the locally-generated sequence
- Builds a **second CIR** (STS CIR) in the accumulator — used by the CIA for a more secure ToA measurement
- STS quality metric available in `STS_QUAL` (CIA diagnostic registers)

The STS key and IV (Initial Vector) must match between transmitter and receiver. They are configured via:
- `STS_KEY` registers (0x11:04)
- `STS_IV` registers (0x11:08)

---

## 4.1.5 PHR Demodulation

The **PHR (PHY Header)** is always demodulated at **850 kb/s rate** (approximately 1.0 Mb/s with BPM/BPSK encoding).

**Exception:** If the `PHR_6M8` bit is set in `SYS_CFG`, the PHR is demodulated at the data rate (6.81 Mb/s). This reduces preamble/PHR overhead but is only useful when the data rate is also 6.81 Mb/s.

If a PHR error is detected (SECDED fails to correct): `RXPHE` (PHR Error) status bit is set and reception is aborted.

---

## 4.1.6 Data Demodulation

After the PHR, the DW3000 demodulates the **PHY payload (PSDU)**:

1. **Viterbi decoder** — corrects convolutional coding errors
2. **Reed-Solomon FEC** — additional error correction (6.81 Mb/s only, as per 802.15.4)
3. **CRC / FCS check** — validates frame integrity

#### RX Status Bits (in `SYS_STATUS`, 0x0F:00)

| Bit    | Name  | Description                                                 |
| ------ | ----- | ----------------------------------------------------------- |
| RXPRD  | —     | Preamble detected                                           |
| RXSFDD | —     | SFD detected                                                |
| RXPHD  | —     | PHR detected (valid PHR received)                           |
| RXFR   | —     | Frame received (data portion done)                          |
| RXFCG  | —     | Frame Check Good — FCS passed; combined with RXFR = success |
| RXFCE  | —     | Frame Check Error — FCS failed                              |
| RXRFSL | RXFSL | Reed-Solomon error                                          |
| RXFTO  | —     | RX Frame Wait Timeout (no frame received within timeout)    |
| RXPTO  | —     | Preamble Timeout                                            |
| RXSTO  | —     | SFD Timeout                                                 |
| RXPHE  | —     | PHR Error (SECDED uncorrectable)                            |
| CIAERR | —     | CIA failed to find a valid leading edge                     |

A **successful receive** requires both `RXFR` and `RXFCG` to be set.

## 4.1.7 RX Timestamp

The final RX timestamp is computed by the **CIA** after frame reception completes:

```
RX_STAMP = coarse_symbol_time - RXANTD + CIA_leading_edge_correction
```

Where:
- `coarse_symbol_time` — derived from RMARKER (SFD detection time)
- `RXANTD` — RX antenna delay calibration value (16-bit, in `LDE_CFG` / `LDE_REPC`, register 0x1E)
- `CIA_leading_edge_correction` — offset computed from CIR first-path peak analysis

The timestamp is **40 bits wide** with ~15.65 ps resolution (same as TX timestamp).

The computed timestamp is written to three locations:
- `RX_TIME` → `RX_STAMP` (0x15:00, 40-bit)
- `IP_TOA` (0x0C) — from Ipatov (preamble) CIR
- `STS_TOA` (0x0D) — from STS CIR (SP1/SP2/SP3 only)

For highest accuracy ranging, use `IP_TOA` or `STS_TOA` directly rather than the combined `RX_STAMP`.

## 4.2 TDoA and PDoA Support

### TDoA (Time Difference of Arrival)

TDoA uses the **difference in receive timestamps** across multiple synchronised anchor nodes. No modification is needed to the standard RX timestamp — anchors simply report their `RX_STAMP` values to a central location engine.

> **Note:** If the CIA quality indicator reports TDoA > 1 ns, the timestamp should be considered untrustworthy and discarded.

### PDoA (Phase Difference of Arrival)

PDoA support is available on the **DW3120** (WLCSP52) and **DW3220** (QFN40) variants only.

PDoA measures the **phase difference of the received signal at two antennas** to determine the angle-of-arrival (bearing) of the transmitter.

Two PDoA modes are supported:

| Mode   | STS Requirement                                      | Output                        |
| ------ | ---------------------------------------------------- | ----------------------------- |
| Mode 1 | Any valid STS (SP1/SP2/SP3)                          | Phase difference from STS CIR |
| Mode 3 | STS length = integer × 128 chips (in 512-chip units) | Higher resolution PDoA        |

PDoA result is read from the `CIA_TDOA_2` / `PDOA_STS` diagnostic registers (0x0E).

## 4.3 Delayed Receive

The DW3000 supports **delayed reception** — the RX enable is held off until a specified future time.

### Absolute Delayed RX

```
CMD_DRX  (fast command 0x03)
DX_TIME register (0x00:40) ← absolute 40-bit time reference
```

The receiver turns on at `DX_TIME`, accounting for RX ramp-up time.

### Reference-Relative Delayed RX

```
CMD_DRX_REF  (fast command 0x04)
DREF_TIME (0x00:48) + DX_TIME (0x00:40) = actual enable time
```

Useful in ranging sequences where the delay is calculated relative to a previously captured TX or RX timestamp.

### HPDWARN

As with delayed TX, if the scheduled time has already passed when the command is issued, the `HPDWARN` bit is set in `SYS_STATUS`. The device will still attempt to enable RX, but timing accuracy is not guaranteed.

> **Rule:** Always check `HPDWARN` after issuing `CMD_DRX` or `CMD_DRX_REF`.

## 4.4 Double Buffering

Double buffering allows the DW3000 to receive a **second frame** while the host MCU is still reading out the first, preventing frame loss in high-throughput or back-to-back scenarios.

### Configuration

- Enabled by clearing `DIS_DRXB` bit in `SYS_CFG` (0x11:00, bit 18) — set to **0** to enable double buffering
- Two RX data buffers: `RX_BUFFER_0` and `RX_BUFFER_1` (each up to 1023 bytes)
- Two register sets: `SET_1` and `SET_2` — each set holds the status, timestamps, and diagnostics for one buffer

### Operation Flow

```
Frame 1 arrives → stored in RX_BUFFER_0, timestamps in SET_1
  │
  │  Host reads RX_BUFFER_0 (frame 1)
  │  Frame 2 may arrive → stored in RX_BUFFER_1, timestamps in SET_2
  │
  │  Host issues CMD_DB_TOGGLE to release buffer 0
  ▼
Frame 1 buffer cleared; DW3000 can now receive into RX_BUFFER_0 again
Host reads RX_BUFFER_1 (frame 2) from SET_2
```

### Key Registers

| Register        | Address        | Description                                |
| --------------- | -------------- | ------------------------------------------ |
| `RDB_STATUS`    | 0x0F:08        | Shows which buffer is active/ready         |
| `CMD_DB_TOGGLE` | —              | Fast command; releases current host buffer |
| `DIS_DRXB`      | SYS_CFG bit 18 | Disable double buffering (0 = enabled)     |

### Overrun Condition

If the host does not issue `CMD_DB_TOGGLE` before a third frame arrives, the `RXOVRR` (RX Overrun) bit is set in `SYS_STATUS`. The overrun frame is discarded. The host must re-enable RX after handling `RXOVRR`.

## 4.5 SNIFF Mode (Low-Power Preamble Detection)

**SNIFF mode** (also called PPDM — Pulsed Preamble Detection Mode) allows the DW3000 to listen for preambles with a low duty cycle, reducing average power consumption.

### Operation

The device alternates between:
- **ON period**: RX active, searching for preamble (duration in PAC units)
- **OFF period**: IDLE_PLL (low power), not listening (duration in µs)

```
[RX ON — SNIFF_ON PACs] → [IDLE_PLL — SNIFF_OFF µs] → [RX ON ...] → ...
```

If a preamble is detected during the ON period, the device stays in RX and completes the full receive sequence normally.

### Configuration Registers

Both fields are in register `0x11:1A`:

| Field       | Bits | Description                | Minimum |
| ----------- | ---- | -------------------------- | ------- |
| `SNIFF_ON`  | 3:0  | ON duration in PAC periods | 2 PACs  |
| `SNIFF_OFF` | 15:8 | OFF duration in µs         | 5 µs    |

> **WARNING:** `SNIFF_OFF` must be ≥ 5 µs to allow the RF front end to restabilise after each IDLE_PLL period. Setting it lower risks missed preambles due to RF not being ready.

### Enabling SNIFF Mode

Set `SNIFF_EN` bit in `RX_SNIFF` register (0x11:1A), then issue `CMD_RX`. The device enters the pulsed preamble detection loop automatically.

## 4.6 Diagnostics

### LED GPIO Indicators

DW3000 can drive GPIO lines as activity indicators (useful during development):

| GPIO  | Default Function | LED Activity           |
| ----- | ---------------- | ---------------------- |
| GPIO5 | General purpose  | RX OK (frame received) |
| GPIO6 | General purpose  | SFD detected           |
| GPIO7 | General purpose  | TX active              |
| GPIO8 | General purpose  | RX active              |

Configure via `GPIO_CTRL` register (0x05).

### CIR Accumulator Memory

The raw CIR data (Channel Impulse Response) is accessible at register `0x15`. This 4-byte-per-tap complex array contains the multipath profile from the preamble accumulation. Used for:
- Debugging ranging accuracy
- NLOS detection
- Manual first-path analysis

Reading the accumulator requires the CIA to have completed. Access is controlled by `ACC_MEM` bits.

### CIA Diagnostic Registers

| Register   | Address | Contents                                                 |
| ---------- | ------- | -------------------------------------------------------- |
| `IP_DIAG`  | 0x0C    | Ipatov (preamble) CIA diagnostics: ToA, F1, F2, F3, C, N |
| `STS_DIAG` | 0x0D    | STS CIA diagnostics: same fields as IP_DIAG              |
| `CIA_TDOA` | 0x0E    | TDoA / PDoA results                                      |

Sub-registers within `IP_DIAG` (0x0C):

| Sub-register | Field | Description                           |
| ------------ | ----- | ------------------------------------- |
| `IP_DIAG_1`  | C     | Preamble CIR power (sum of magnitude) |
| `IP_DIAG_2`  | F1    | First path amplitude sample 1         |
| `IP_DIAG_3`  | F2    | First path amplitude sample 2         |
| `IP_DIAG_4`  | F3    | First path amplitude sample 3         |
| `IP_DIAG_12` | N     | Preamble accumulation count           |

Equivalent `STS_DIAG_1/2/3/4/12` fields exist for STS-based measurements.

## 4.7 RX Signal Quality Estimation

### First-Path Power (dBm)

Used to estimate the power level of the **first arriving path** (most relevant for ranging):

```
P_firstpath = 10 × log10((F1² + F2² + F3²) / N²) + (6 × D) − A
```

Where:
- `F1`, `F2`, `F3` — first-path amplitude samples from `IP_DIAG_2/3/4` (Ipatov) or `STS_DIAG_2/3/4` (STS)
- `N` — preamble accumulation count from `IP_DIAG_12` or `STS_DIAG_12`
- `D` — `DGC_DECISION` field from `DGC_DBG` register (gain step applied by Digital Gain Control)
- `A` — PRF-dependent constant:

| PRF / Sequence  | A value |
| --------------- | ------- |
| 16 MHz (Ipatov) | 113.8   |
| 64 MHz (Ipatov) | 121.7   |
| 64 MHz (STS)    | 120.7   |

### RX Level (dBm)

Used to estimate **total received signal power** (all paths, including multipath):

```
P_rx = 10 × log10(C × 2²¹ / N²) + (6 × D) − A
```

Where:
- `C` — CIR power sum from `IP_DIAG_1` or `STS_DIAG_1`
- `N`, `D`, `A` — same as above

> **Note:** `P_firstpath` is typically lower than `P_rx` in NLOS environments, as reflected paths add to the total power but arrive after the first path. A large difference between the two values is an indicator of NLOS conditions.
